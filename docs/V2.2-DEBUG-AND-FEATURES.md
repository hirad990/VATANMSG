# VATANMSG 2.2 — Debug & Feature Plan

This checklist separates features already present in the repository from new work.
A listed idea is **not implemented merely because it appears here**; each feature
needs API/UI work and a test before being marked complete.

## Reliability and security first

- [ ] Persist profile-photo uploads through a dedicated authenticated endpoint. Current profile editor only stores the selected local URI in app state; `saveProfile` does not upload it, so it cannot persist across devices.
- [ ] Add automated tests for API response normalization and HTTP error handling.
- [ ] Add API integration tests for registration, login, session expiry, and profile updates.
- [ ] Validate upload MIME type, size, ownership, and storage permissions on the server.
- [ ] Add rate limits for authentication, message sending, search, and uploads.
- [ ] Add pagination/cursor support for conversation history and user/message search.
- [ ] Add reliable reconnect/backoff and duplicate-message reconciliation.
- [ ] Audit all membership/role checks for group and channel operations.
- [ ] Add database migration smoke tests against a clean and an upgraded schema.
- [ ] Add release APK signing verification and checksum output to CI.

20. Optional app lock using device biometrics/PIN.

## Definition of done

A feature is complete only when its UI is connected to a real API/data model,
permission checks are enforced server-side, loading/empty/error states are present,
and a regression test covers its critical path. Do not ship mock-only controls as
working features.
